# 常见问题（FAQ）

## 执行与记录

### 已经执行过的标识，怎么再执行一次？

执行重置后即可再次运行：

```text
/ic run once reset global welcome      # 重置单条
/ic run once resetall player           # 重置玩家作用域下全部记录
/ic run once resetall                  # 重置全部记录
```

未重置时重复执行只会提示 `[IC-Once] 标识 'xxx' 已在{作用域}执行过……` 并返回 `0`。

### 命令执行失败了，为什么下次还能执行？

这是预期行为：只有命令**执行成功**（未抛异常）才会写入记录。命令解析失败、权限不足、运行报错时返回 `0` 且不记录，修好后可重新执行。

### 服务器重启后记录还在吗？

在。记录以 `SavedData`（数据名 `once_records`）保存在主世界的存档数据中，随存档加载/保存，跨重启有效。只有删除存档数据文件或整个存档才会丢失记录。

### 控制台/命令方块执行 player 作用域，为什么变成全局共用一次？

`player` 作用域的键依赖玩家 UUID；控制台、命令方块等没有玩家实体的执行源无法取得 UUID，键会退化为 `global:<标识>`。要在每个玩家身上各执行一次，请以玩家身份执行，或在函数中配合 `as @a` 使用（此时执行源仍是玩家）。

### 不同作用域会互相干扰吗？

不会。三类作用域使用不同前缀的键（`global:` / `player:` / `dimension:`），同一标识在不同作用域、不同玩家、不同维度下各自独立记录。

## 命令与权限

### 输入 `/ic run once ...` 没有补全也不执行？

按顺序排查：

1. **权限**：子命令要求 GAMEMASTERS（OP 2 / 控制台），且 `/ic` 根命令要求 IC-Root 的 moderator 权限；权限不足时命令不可见也不可执行。先 `/op 你的名字` 或在控制台测试。
2. **IC-Once 是否加载**：日志中搜索 `已初始化，命令入口：/ic run once`。
3. **IC-Root 是否安装**：IC-Once 硬依赖 `ic-root >= 0.1.0`，缺失时加载器会在启动阶段直接报错。

### 提示「不允许递归调用 /ic run once 命令」？

这是递归保护。命令内容若以 `once ` 开头、等于 `ic run once` 或以 `ic run once ` 开头（允许前导 `/`），会被拒绝执行且不记录，防止 `/ic run once run ...` 嵌套调用造成无限递归。

### 提示「标识不能包含空格」，但我没写空格？

该错误覆盖三种校验失败：标识含空格、命中保留字、超过 256 字符。保留字共 8 个（不区分大小写）：

```text
global  player  dimension  strict  loose  reset  resetall  list
```

### 标识参数补全不出来？

补全只列出**已存在的记录键**（显示 `:` 之后的部分），没有记录时自然无候选。命令内容参数则按原版规则补全服务器命令。

### 普通玩家能执行内部命令提权吗？

不能。`/ic run` 保留原命令源、不提升权限，目标命令自身的权限检查仍然生效；且普通玩家本就看不到需要 GAMEMASTERS 的子命令。

## 作用域与重置

### resetall 会删掉其他作用域的记录吗？

不带参数的 `/ic run once resetall` 删除**全部**记录；带作用域参数（如 `/ic run once resetall dimension`）只删除该作用域前缀下的记录。

### list 显示的一长串键是什么？

显示的是完整存储键，例如 `global:welcome`、`player:<UUID>:join`、`dimension:minecraft:overworld:first`。冒号前是作用域与作用域值，冒号后是你指定的标识。

### reset 提示「不存在」，为什么还返回 1？

`reset` / `resetall` / `list` 是管理命令，命令本身执行成功即返回 `1`；记录是否真的被删除以消息文案为准（`已重置…` 为成功，`不存在` 为未匹配到记录）。

### 想彻底清空记录文件？

游戏内用 `/ic run once resetall` 即可清空全部记录并立即写回存档；直接删除存档数据文件需要在世界卸载后进行，请谨慎操作。

## 返回值

### 返回值在哪里看？

命令返回值不是聊天消息，供以下场景读取：

- **命令方块**：比较/存储命令结果（`run` 成功 `1`、已执行/失败 `0`）
- **函数（function）**：配合 `execute if score` 等判断是否已执行过
- **自动化/脚本**：通过 RCON 或命令执行 API 读取

`/ic run once list` 等管理命令恒返回 `1`，是否为空以消息为准。
